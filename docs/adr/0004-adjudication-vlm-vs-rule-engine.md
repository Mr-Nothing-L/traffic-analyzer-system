# 裁决层采用 VLM 语义判断而非确定性规则引擎

## 背景

裁决层接收全部事件专家的候选,需要做跨事件冲突裁决——哪些候选保留、哪些排除(如"事故场景中静止车辆不重复判定为违停"、"应急车道静止→双事件触发")。这类冲突场景开放且语义复杂。

## 决策

裁决用单次 VLM 调用做语义判断,而非确定性规则引擎(if-else)。裁决规则以文本形式(`event_categories.yaml` 的 `adjudication_rules`)嵌入裁决 prompt,VLM 根据全部候选的上下文做全局判断。

## 原因

交通事件的冲突模式开放且依赖语义推理——同样"车辆静止",在事故场景下不算违停、在施工区域内仍算违停、在应急车道上同时触发两个事件。用硬编码 if-else 难以枚举所有边界组合,VLM 的语义推理天然适合这类模糊判断。

## 代价

- **非确定性**:同一视频多次分析可能产出不同裁决结果(不同的 VLM 温度/采样)。系统通过缓存(VLM cache)减少重复调用,但无法完全消除。
- **JSON 完整性不保证**:裁决 VLM 的 JSON 输出可能遗漏事件类别,代码层面有重试+降级回填补偿(见 [ADR-0003](0003-three-layer-review-architecture.md) 影响部分)。
