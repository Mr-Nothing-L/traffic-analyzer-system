# 配置驱动 + 事件级硬编码特例的混合策略

## 背景

CLAUDE.md 声明"新增事件无需改代码,只需追加 YAML 配置"。这对纯 VLM 判断的事件类别成立——加一个新事件类别只需在 `event_categories.yaml` 定义 + 在 `prompt_templates/` 加模板。但部分事件类别在代码中有按 `event_id` 硬编码的特殊逻辑。

## 决策

采用"配置驱动为主、事件级硬编码特例为辅"的混合策略:

**纯配置可新增的事件**(零代码):违法停车(1)、交通事故(3)、严重拥堵(6)、道路施工(7)、车辆逆行(8)、抛洒物(10)、实线变道(11)。只需 YAML 定义 + prompt 模板。

**需要代码改动的事件特例**:
- 行人(4)、摩托车(5):远距离增强中的汽车语义否决(car veto)按 event_id 硬编码,新增同类事件需在 `_select_car_veto_check()` 中注册。
- 应急车道占用(2):掩膜生成、缩放网格、区域重叠计算(`emergency_lane_occupancy.py`)是专属实现。

## 原因

通用 VLM prompt 能覆盖大多数事件的视觉识别,但远距离小目标的误判修正(行人/摩托车被误判为汽车)和车道级几何推理(应急车道 ROI)需要超出 prompt 的信号处理——ROI 运动、掩膜、关键词匹配。这些逻辑与特定事件类别强绑定,难以泛化为通用配置项。

## 影响

新增事件时,先判断是否需要远距离增强或车道几何推理。若需要,除了 YAML 配置外还须编写对应的 `event_id` 分支逻辑。CLAUDE.md 的"新增事件无需改代码"声明应补充这一前提。
